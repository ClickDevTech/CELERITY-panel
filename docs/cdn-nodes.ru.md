# CDN-ноды

CDN-нода публикует один WebSocket, gRPC или XHTTP inbound существующей
Xray-ноды через любой CDN или reverse proxy. У неё нет SSH-хоста и отдельного
процесса Xray.

## Требования

- Источником должна быть активная Xray-нода.
- Выбранный inbound должен использовать WebSocket, gRPC или XHTTP с TLS либо
  без транспортного шифрования. REALITY несовместим с CDN, завершающим TLS.
- Нужен хотя бы публичный домен CDN или один edge-адрес.
- Для клиентского TLS требуется SNI. Если задан домен, он по умолчанию
  используется как SNI и Host.

Чтобы скрыть origin от прямой публикации, не добавляйте его в группы
пользователей. Вместо него добавьте в группы CDN-ноду.

## Режимы адресов

- Только домен: в подписке создаётся одна запись с доменом CDN.
- Закреплённые edge: каждый включённый адрес становится отдельной записью.
  Домен остаётся необязательным и может использоваться для SNI/Host и
  DNS-поиска.

Кнопка поиска edge получает текущие A- и AAAA-записи домена и копирует их в
редактируемый список. Автоматического фонового обновления списка нет.

## XHTTP через CDN

Какие клиентские пути примет XHTTP-origin, зависит от того, где лежат его
маркеры session и sequence:

- Размещение по умолчанию (`path`): клиент дописывает маркеры к своему пути, а
  инбаунд читает их как сегменты после своего префикса. Поэтому клиентский path
  должен быть пустым или в точности равным origin path — более длинный, вроде
  `/api/events.php` при origin `/api`, заставит инбаунд считать `events.php`
  идентификатором сессии сразу для всех клиентов.
- Любое другое размещение (query, header, cookie): путь не несёт маркеров,
  инбаунд проверяет только префикс, и CDN может публиковать более длинный путь,
  похожий на обычный веб-ресурс.

С WebSocket path сравнивается точно, поэтому клиентский path нужно либо
оставить пустым, либо задать в точности как у origin.

Расширенные параметры XHTTP доступны для основного и дополнительных inbound:
HTTP-метод и размещение загрузки, размеры блоков, обфускация padding,
размещение session и sequence. Клиенту они уходят во всех формах, которые он
умеет читать: плоскими `snake_case`-ключами в VLESS URI для семейства
sing-box, объектом `extra` в том же URI для семейства Xray и нативными ключами
транспорта в JSON-профилях sing-box и Xray.

В `xhttp-opts` Mihomo есть только path, mode и host, поэтому инбаунд с
согласованным framing в Clash-профиле невыразим. Такой инбаунд не попадает в
Clash-подписку — вместо прокси, который выглядит рабочим и падает на каждом
запросе. Во всех остальных форматах он остаётся.

## Изменение origin

Xray-ноду, на которую ссылаются CDN-фронты, нельзя удалить и нельзя сменить ей
тип, транспорт инбаунда или транспортное шифрование, пока эти фронты
существуют. Панель, REST API и MCP-инструмент откажут в правке и назовут ноду,
которая её блокирует, — иначе фронты продолжили бы публиковать записи для
инбаунда, которого в таком виде больше нет.

CDN-ноды не поддерживают Hysteria 2: Hysteria использует QUIC/UDP, а этот тип
ноды предназначен для HTTP-транспортов CDN.
